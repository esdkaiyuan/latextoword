# 整份文档编辑工作区设计

## 目标

在公式工作台中增加独立的文档工作区，让用户可以打开整份文档，在应用内编辑、预览和保存；同时保留当前公式提取、LaTeX 编辑和公式预览能力。不同格式按其本身能力提供编辑，不以“能导入”冒充“可无损编辑”。

## 设计决策

新增顶层“文档”工作区，与现有“公式”工作区并列。文档以单独的打开文档状态管理，包含源路径、格式、编辑内容、脏状态、格式警告及保存目标。原文件不在导入或编辑过程中被隐式覆盖；首次编辑转换型格式时明确告知转换限制，并默认另存为。

编辑器按格式使用适合的交互方式：结构化文本使用源码编辑与渲染预览；DOCX/ODT 使用富文本编辑与分页/打印预览；PDF 保持原版分页作为固定版面预览，提供选取、搜索和批注。顶部仍提供提取公式到现有公式工作台的入口。

## 格式能力矩阵

| 格式 | 打开与预览 | 应用内编辑 | 保存/导出 | 保真承诺 |
|---|---|---|---|---|
| Markdown、TXT、LaTeX、HTML、RTF 及可解码的科研文本 | 全文读取；Markdown/HTML/LaTeX 提供格式预览，并渲染数学公式 | 编辑完整源码 | 保存为原格式；支持另存为 | 文本内容与未编辑源码保留；渲染器不替代源文件 |
| DOCX、ODT | 文档结构和分页预览 | 编辑常用段落、标题、列表、表格、图片、超链接与公式 | 导出 DOCX；支持另存为 | 常用内容尽量保留；复杂布局、修订/批注、宏、特殊域、嵌入对象可能被简化，转换前提示 |
| 旧版 DOC | 先尝试桌面本地转换为可编辑文档 | 转换成功后按 DOCX 编辑 | 保存为 DOCX 或另存转换副本 | 原 DOC 不直接覆盖；转换结果可能有布局差异 |
| PDF | PDF.js 分页预览、页码导航、缩放、文本选择与搜索 | 在页面上添加/移动/删除高亮与文字批注；扫描 PDF 可 OCR 后生成可编辑副本 | 保存原 PDF 的批注副本；OCR 结果可另存为 Markdown/DOCX | 不承诺重排、替换原 PDF 的任意正文文字；OCR 副本与原版式分离 |
| PPTX、XLSX、EPUB、Jupyter Notebook、图片及其他已支持导入格式 | 保留当前可用的查看、转换或公式提取入口 | 只有存在明确编辑适配器的格式才启用编辑；其余只读并标示能力 | 按格式适配器提供导出；否则保持原文件并允许导出转换副本 | 不承诺由公式提取支持推导出整文档编辑能力 |

## 交互与布局

- 顶部增加“公式 / 文档”工作区切换，不改变公式工作台既有三栏布局和状态。
- 文档工作区左侧为文档/页面导航及格式信息，中间为编辑区，右侧为可折叠预览；窗口变窄时可切换编辑/预览，而不强行挤压内容。
- Markdown 等源码型格式默认左右分屏，编辑时实时预览；支持同步滚动开关。
- DOCX/ODT 默认使用富文本编辑画布，分页预览可并排或独立展开；格式转换警告与保存目标始终可见。
- PDF 默认展示页面画布，批注工具和 OCR 转可编辑副本入口置于工具栏；每页有独立页面导航，内容滚动保持在页面视图内。
- 文件名、格式、未保存状态、保存/另存为、撤销/重做和提取公式是文档工作区的共同命令。

## 文档与格式适配架构

- `DocumentWorkspace` 负责已打开文档、编辑状态、脏状态、错误与格式能力展示，不把文档内容塞进现有公式 `ProjectFile`。
- 共享文档模型保存文档身份和来源，并以格式特定的内容联合类型表示源码文档、富文本文档、PDF 页面/批注及只读预览；未解析或不支持的结构必须保留为警告或只读节点，不能静默丢弃。
- 格式适配器提供 `open`、`render`、`save`、`saveAs`、`extractFormulas` 与能力声明。UI 根据能力声明显示对应编辑命令。
- Electron 主进程负责原生打开/另存为对话框、受控文件读写与格式转换 IPC；渲染进程不获得任意文件系统访问权限。保存前校验文档格式与目标扩展名，写入失败保留当前编辑状态。
- 格式解析和导出限制以可读警告呈现，保留原件作为恢复源；用户未明确确认时不上传文档到在线 OCR。

## 保存、撤销与错误处理

- 文档独立维护撤销/重做及未保存提示，关闭文档或切换工作区不会静默丢弃修改。
- 源码型文件保存原扩展名和 UTF 编码信息；未知编码在打开时提示解码方式/替换字符风险。
- DOCX/ODT 的转换型保存默认另存副本，显示转换前后支持差异；保存成功后更新文档的当前路径与脏状态。
- PDF 批注作为增量/覆盖层写入副本，始终不改变未另存的原件；扫描 PDF OCR 失败时保留原 PDF 并说明失败页。
- 密码保护、损坏、超大、类型签名不匹配或格式能力不足时，提供明确原因、可执行的备用操作（只读打开、另存转换副本、继续公式提取或系统程序打开）。

## 隐私与安全

- 默认只在本地读取、编辑和保存。
- 在线 OCR 仍采用显式选择、上传前确认、凭据安全存储和任务状态提示；整份文件未经确认不上传。
- HTML、DOCX 外部资源及嵌入内容以安全方式渲染；脚本、活动内容和外部自动加载默认禁用。
- PDF/Office/XML/ZIP 输入限制大小、拒绝路径穿越和异常压缩包条目；解析失败不能阻塞主进程。

## 验收标准

1. 用户可以从“打开文件”选择 Markdown/TXT/LaTeX，查看完整正文，编辑、实时预览并保存；编辑的数学公式在预览中正常渲染，源码保持可继续编辑。
2. 用户可以打开 DOCX/ODT，在应用内编辑常见正文和表格内容，预览转换结果并另存 DOCX；不支持的复杂结构在编辑前有清晰警告，原件不被覆盖。
3. 用户可以打开多页 PDF，分页查看、搜索文本、添加并保存高亮/文字批注副本；扫描页可以启动本地 OCR 并将识别结果作为独立可编辑文档打开。
4. 既有公式集合、LaTeX 编辑、MathML/Word 公式复制、项目保存和公式提取不因文档工作区而退化。
5. 文档未保存时关闭/切换有确认；解析、保存、转换错误会给出可理解反馈且不丢失内存中的修改。
6. 格式列表对每种类型明确区分“可编辑、批注、只读/转换、公式提取”，不将仅能预览或提取公式的格式标成可编辑。

## 不在本阶段承诺

- 对任意 PDF 原文进行无损段落重排和替换。
- 完整复刻 Microsoft Word 的所有页面布局、修订记录、宏、字段和嵌入对象。
- 对每种 Office、出版和科研文件格式提供完整的原生编辑器。
- 在没有专用编辑适配器时，对只读格式静默转换并覆盖原文件。
